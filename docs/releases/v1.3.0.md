# Linkex Downloader v1.3.0 — DL=8高速パイプラインとreload復旧

v1.3.0は、Linkex側の破壊操作を1件ずつ厳密に制御したまま、ローカルDOWNLOADを最大8並列へ拡張するminor releaseです。通常の「すべてダウンロード」「選択をダウンロード」は高速DL=8を使用し、従来のLOCAL_COMMITTED後DELETE方式も互換モードとして残します。

> [!IMPORTANT]
> 本ツールはLinkex公式とは無関係の非公式ツールです。Linkex側のWeb / API / CDN仕様変更により将来動作しなくなる可能性があります。

## 高速モード

各ファイルのcontrol-planeは直列です。

```text
shared file
  -> COPY to own Linkex storage
  -> prove ownership of the new destId
  -> obtain fresh signed CDN URL (memory-only)
  -> recheck exact owned identity
  -> DELETE exactly that owned temporary destId
  -> confirm absence
  -> local DOWNLOAD / VERIFY (up to 8 workers)
```

設定:

- COPY workers: 1
- early DELETE workers: 1
- local DOWNLOAD workers: 8
- max in-flight detached transactions: 16
- signed URL persistence: false
- processing order: manifest order

## 安全条件

高速化で共有元削除や曖昧DELETEを許可していません。

- 共有元ファイルはDELETE対象にしない
- COPY前から存在したIDはDELETEしない
- ownershipが一意に証明できた新規`destId`だけ対象
- fresh signed URL取得元とownership確定IDを一致確認
- DELETE直前にown root上のname / metadata size / IDを再確認
- DELETEは常に`select_all:false` + 単一`file_ids:[destId]`
- COPY / DELETE結果不明時は同じwriteを盲目的に再送せず、実状態を先にreconcile
- signed URLは永続化しない
- lease喪失時は停止する

「互換: 保存後DELETE」はv1.2系と同じく、ローカル`LOCAL_COMMITTED`後だけ一時copyをDELETEします。

## early DELETE後の復旧

early DELETE後に通信切断・reloadでsigned URLを失っても、削除済みdestIdを再利用しません。

1. ローカルpartialはそのまま保持
2. 新しいCOPYを作成
3. 新しいownership / signed URLを取得
4. 新しい一時copyをDELETE・不在確認
5. 既存partialの現在サイズからRange resume
6. CDN実サイズまたはstream EOFで最終ローカル完全性を検証

real page exitでは、その実行コンテキスト自身が所有するleaseだけを解放します。BFCacheではleaseを保持し、クラッシュ等でpagehideが来ない場合は従来のlease TTLへフォールバックします。別tabの有効leaseを強制取得しません。

## 性能

同じ26ファイル / 約6.37 GBの実測:

| 構成 | Pool | Queue実効 | Queue wall |
|---|---:|---:|---:|
| 従来DOWNLOAD=2 | 62.03 MiB/s | 60.26 MiB/s | 100.85 s |
| early-delete DL=4 | 74.32 MiB/s | 72.19 MiB/s | 84.19 s |
| early-delete DL=6 | 76.08 MiB/s | 73.92 MiB/s | 82.22 s |
| **early-delete DL=8** | **77.14 MiB/s** | **74.93 MiB/s** | **81.11 s** |

size-desc順も検証しましたが、8本同時転送を長時間維持しても通常順DL=8比でQueue実効+約0.27%だったため採用していません。

## UI

- **すべてダウンロード**: DL=8高速Full Queue
- **選択をダウンロード**: 選択ファイルをDL=8高速Queue
- **互換: 保存後DELETE**: 従来方式のFull Queue
- **互換: 選択 保存後DELETE**: 従来方式の選択Queue
- fault-injection / signed-URL検証用ボタンは安定版UIには表示しません

## 更新時の注意

未完了のv1.2.x Queueをversion跨ぎで再開する全パターンは実機網羅していません。可能なら更新前に既存Queueを完了、または安全停止・整理してからv1.3.0へ更新してください。
