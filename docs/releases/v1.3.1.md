# Linkex Downloader v1.3.1 — Worker転送・stream先行DELETE・大量小ファイル高速化

v1.3.1は、v1.3.0のDL=8安全パイプラインを維持しつつ、大量の小ファイルで支配的だったCOPY/ownership/DELETE周辺の固定コスト、Manifestの直列待ち、巨大Queueのpersistent storage書き込みを削減するpatch releaseです。

Chromium系 + Tampermonkeyの実機再テストで、更新前よりダウンロード処理が高速化したことを確認しています。

> [!IMPORTANT]
> 本ツールはLinkex公式とは無関係の非公式ツールです。Linkex側のWeb / API / CDN仕様変更により将来動作しなくなる可能性があります。

## 主な高速化

- 共有Manifestのfolder fetchを最大6並列化
- Manifest進捗UIを250msへthrottleし、中間進捗のpersistent event log書き込みを停止
- CDN fetch / ReadableStream / File System Access書き込みをWeb Workerへ移行
- ローカルDOWNLOADは最大8並列
- CDN streamの最初のchunkを確認してから所有一時copyのDELETEを開始
- DELETE確認とローカルDOWNLOADを並行
- early DELETE workerを最大2へ拡張
- COPY taskの初回poll待ちを短縮
- 容量判定をlocal reservation ledger中心にし、毎ファイルの不要なusage APIを削減
- ownership reconcileで取得済みroot snapshotを次のCOPY baselineへ再利用
- freshly reconciled signed URLをmemory-onlyでそのまま利用し、不要なroot再取得を削減
- 数千件Queue全体のGM storage保存を各phaseごとに行わず、item journal + 最大5秒batch flushへ変更

## stream-before-delete

高速モードは次の順で動きます。

```text
shared file
  -> COPY to own Linkex storage
  -> prove ownership of the new destId
  -> obtain signed CDN URL in memory
  -> start CDN stream in Web Worker
  -> observe first non-empty chunk (or valid zero-byte EOF)
  -> recheck exact owned identity
  -> DELETE exactly that owned temporary destId
  -> confirm absence while DOWNLOAD continues
  -> local VERIFY
  -> DONE
```

DELETE前にstreamが実際に開始したことをbarrierとして要求するため、旧v1.3.0の「DELETE完了後にDOWNLOAD開始」より待ち時間を重ねられます。

## 復旧 / 永続化

- Worker transfer中のcheckpointはmain側のoperation stateへ保存
- file単位のitem journalをwrite-ahead logとして保存
- Full Queue本体は最大5秒間隔でまとめて保存
- reload時はFull Queueへjournalを重ねて最新stateを復元
- pre-DELETEの `DOWNLOAD_READY` / `DOWNLOADING` / `DOWNLOAD_PAUSED` / `VERIFY_FAILED` も安全再開対象
- DELETE intent/requestが不明な場合、DELETE POSTは再送せず存在/不在を先にreconcile
- signed URLは引き続き永続化しない

## 安全条件

速度のためにownership証明は弱めていません。

- 共有元ファイルはDELETEしない
- COPY前から存在したIDはDELETEしない
- ownershipを一意に証明できた新規 `destId` だけ対象
- DELETE直前にID / name / metadata sizeを再確認
- DELETEは常に `select_all:false` + 単一 `file_ids:[destId]`
- COPY / DELETE結果不明時のwrite盲目的再送は禁止
- signed URLはmemory-only
- lease喪失時は停止
- COPY APIはdestIdを直接返さないため、曖昧性を増やすCOPY並列化は行わずCOPY=1を維持
- Web Workerが使えない環境では従来inline転送へfallback

## 診断

background tabでの停止を次回ログから切り分けられるよう、以下をsupport bundleへ記録します。

- Web Worker transfer数
- Worker fallback
- `visibilitychange`
- `freeze` / `resume`
- userscript event-loop stall
- 5秒以上のAPI request
- HTTP `Date` が得られる場合のresponse callback lag
