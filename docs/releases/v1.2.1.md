# Linkex Downloader v1.2.1 — Content-LengthなしCDN応答への対応

v1.2.1は、CDNが `Content-Length` を公開しない正常応答でQueueが停止する問題を修正するpatch releaseです。v1.2.0の所有権確認・単一ID削除・write再送禁止などの安全条件は維持します。

> [!IMPORTANT]
> 本ツールはLinkex公式とは無関係の非公式ツールです。Linkex側のWeb / API / CDN仕様変更により将来動作しなくなる可能性があります。

## 修正内容

- CDN応答に `Content-Length` がある場合は、従来どおり期待CDN byte数と最終ローカルサイズを厳密照合します。
- `Content-Length` がない場合は、streamの正常EOF到達・stream実書込byte数・最終ローカルサイズの一致を検証し、`verificationMethod: stream-eof` として完了できます。
- stream途中切断やreader例外は `DOWNLOAD_PAUSED` とし、`LOCAL_COMMITTED` にはしません。
- Range再開時にHTTP 416となり、追加probeでも総byte数を得られない場合は、曖昧なローカルファイルを完成扱いせず0 byteから安全に再取得します。
- Linkex metadataの `size` をCDN実サイズの代替には使用しません。
- DONE transaction compact化後も `verificationMethod` / `streamComplete` を保持します。

## 削除安全条件

一時コピーの自動DELETEは `LOCAL_COMMITTED` 後だけです。

- Content-Length方式: `sizeVerified === true` かつ `downloadedBytes === expectedCdnBytes >= 0`
- stream EOF方式: `verificationMethod === 'stream-eof'`、`streamComplete === true`、stream実書込byte数と最終ローカルサイズが一致
- どちらも `verifiedAt` が必要
- ownership確定済み `destId` だけを `select_all:false` + 単一 `file_ids:[destId]` で削除

stream EOF方式は、サーバーが明示する総byte数との独立照合ではなく、正常なtransport EOFと実書込byte数を完全性証拠として使用します。Content-Lengthが得られる場合は従来の厳密なsize一致を優先します。

## 回帰テスト

- Content-Lengthなし + 正常EOF → `LOCAL_COMMITTED`
- Content-Lengthなし + stream途中切断 → `DOWNLOAD_PAUSED`、未commit
- Range 416 + probeでもContent-Lengthなし → 0 byteから再取得しstream EOF検証
- 既存の0 byte / 416既知サイズ / ownership変更 / lease / retryケース

## 実機確認

2026-09-17に、実際に `Content-Length` 不在で停止していたファイルを含むQueueで修正版の動作確認を実施済みです。

## インストール / 更新

GitHub Release `v1.2.1` の `linkex_downloader_v1.2.1.user.js` を推奨Assetとします。ZIPは同じuserscriptを1ファイルだけ含む補助Assetです。

未完了Queueがある場合は、可能なら更新前に安全停止してからuserscriptを更新してください。
