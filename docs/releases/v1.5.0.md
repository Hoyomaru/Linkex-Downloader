# Linkex Downloader v1.5.0 — development candidate

> **Status:** 未公開 / 開発中。GitHub Release・tagはまだ作成していません。

## Scope

v1.5.0候補は、v1.4.0の通常操作・direct-save・高速pipelineを維持しつつ、安全性修正と「複数共有リンクの一括取り込み」だけを新機能として追加します。

### Safety fixes

- COPY/task応答のcreated/destination IDまたはtask IDとroot candidateを直接結び付けられる場合だけownership確定する。
- 同名・同サイズ・単一ID差分だけではownership確定せず、安全停止する。
- Range resumeの206は `Content-Range` startを要求offsetと照合し、検証不能/不一致なら0 byteから取り直す。
- direct-save targetはQueue metadataとFileHandleの永続化が終わるまでtruncateしない。
- destructive DELETEは `ownershipProof.verified === true` を必須にする。

### New feature

- 複数共有URLを貼り付け、親バッチが共有ごとの既存高速Queueを順次実行する。
- 保存先選択は1回。
- 親バッチをGM storage、保存先DirectoryHandleをIndexedDBへ保持してreload後も再開する。
- 容量skipが発生した共有では一旦停止し、再試行または次共有への継続を利用者が選べる。

### Reproducibility

- test harnessでCRLFをLFへ正規化。
- `.gitattributes` でtext checkoutをLFへ固定。
- Release Asset builderもLF-normalizeしてOS間で同一bytesを生成する。

## Verification boundary

Node回帰テスト、userscript構文、repository consistency、Release Asset生成はCIで確認する。実Linkex APIがCOPY作成IDをどの形で返すか、CDNが `Content-Range` をCORS公開するか、複数共有の長時間実機動作は別途ブラウザ結合確認が必要。
